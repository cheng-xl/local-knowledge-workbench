## Local Knowledge Workbench

> **版本**：1.1.0 | **状态**：核心功能完成，测试全通过 | **最后更新**：2026-07-30

## 1. 项目概述

### 1.1 背景与目标

本项目构建一个运行在本地电脑上的智能知识工作台，同时作为学习 **LangGraph Agent**、**RAG** 和 **MCP 协议** 三项核心技术的工程实践项目。核心能力包括：

- 基于用户上传的文档（PDF、Word、Markdown、TXT）进行精准问答（RAG 全流程）
- 通过 Agent 自主调用工具（计算器、日期时间、文件操作）（LangGraph 状态图编排）
- 支持状态化任务流程与人工确认节点（Human-in-the-Loop 模式）
- 集成 MCP 协议，展示标准化的工具调用架构

### 1.2 技术能力覆盖

本项目完整覆盖 Agent 开发岗位的核心技术要求：

- **RAG 全流程**：文档加载 → 分块 → Embedding → 多路检索 → 重排序（混合检索 + Cross-encoder）
- **LangGraph 状态化 Agent**：图结构定义、条件分支、循环控制、人工确认节点
- **向量数据库实操**：Chroma 持久化存储 + 元数据过滤 + 来源管理
- **MCP 协议**：自建 MCP Server（只读文件系统）+ 路径安全校验
- **工程化能力**：重试机制、结构化日志、pytest 回归测试（33 个）、pydantic-settings 配置管理

### 1.3 运行环境

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows / macOS / Linux（Python 跨平台） |
| Python 版本 | 3.10 及以上 |
| 硬件建议 | 4GB RAM（云端 API 模式，无需 GPU） |
| 网络要求 | 需联网（Embedding 和 Reranker 使用云端 API） |
| 依赖管理 | pip + requirements.txt（推荐使用 venv 虚拟环境） |

## 3. 系统架构

### 3.1 整体架构

```
Streamlit UI (app.py)
    [文档上传]  [智能问答]  [思考链追踪]  [运行日志]
         │
    LangGraph Agent (agent_graph.py)
    ┌──────────────────────────────────────────────┐
    │  retrieve → decide → execute → reflect → answer  │
    │                │         ↑                     │
    │          human_confirm──┘  loop ───────────────┘ │
    │          retrieve_again ────────────────────────┘ │
    └──────────────────────────────────────────────┘
         │              │              │
    ┌────┴────┐   ┌─────┴─────┐  ┌───┴──────────┐
    │ Chroma  │   │ MCP Server│  │ Local Tools   │
    │ 向量库  │   │ (只读文件) │  │ 计算器/日期   │
    └─────────┘   └───────────┘  └──────────────┘
         │
    SiliconFlow API
    (Embedding + Reranker)
```

### 3.2 Agent 状态定义

```python
class AgentState(TypedDict):
    messages: Annotated[List[dict], operator.add]  # 对话历史（累加）
    retrieved_docs: List[Document]                  # 检索结果
    tool_calls: List[dict]                          # 待执行工具调用
    need_human_confirm: bool                        # 是否需要人工确认
    loop_count: int                                 # 循环计数器
    decision: str                                   # 当前决策结果
```

### 3.3 状态流转说明

| 节点 | 职责 | 出边条件 |
|------|------|----------|
| `retrieve` | 调用 RAG Pipeline 混合检索相关文档块 | 无条件 → `decide` |
| `decide` | LLM 判断下一步动作 | 4 路分支：`tool` / `answer` / `human_confirm` / `retrieve_again` |
| `execute` | 关键词匹配选择工具并执行调用 | 无条件 → `reflect` |
| `reflect` | 评估执行结果是否充分，控制循环次数 | 2 路：`continue` → `decide` / `end` → `answer` |
| `human_confirm` | 暂停图执行，等待用户在 UI 中确认 | 确认后 → `execute` |
| `answer` | 汇总上下文与工具结果，生成最终回复 | → `END` |

### 3.4 核心数据流

1. 用户上传文档 → 解析 → 分块 → 调用 SiliconFlow API 生成 Embedding → 存入 Chroma
2. 用户提问 → `retrieve` 混合检索（向量 + BM25 + RRF 融合 + Reranker 重排序）
3. `decide` 判断：可直接回答 → `answer`；需工具 → `execute`
4. `reflect` 评估：不足且未超循环上限 → 回到 `decide`；充分 → `answer`
5. 敏感操作 → `human_confirm` 暂停并等待用户在 UI 中确认

## 5. 核心模块实现详解

### 5.1 配置模块（config.py）

使用 pydantic-settings 管理所有配置，支持 .env 文件和环境变量覆盖。

```python
class Settings(BaseSettings):
    # LLM — DeepSeek (OpenAI 兼容)
    openai_api_key: str = ""
    openai_base_url: str = "https://api.deepseek.com/v1"
    model_name: str = "deepseek-chat"

    # SiliconFlow API (Embedding + Reranker)
    siliconflow_api_key: str = ""
    siliconflow_base_url: str = "https://api.siliconflow.cn/v1"
    embedding_model: str = "Qwen/Qwen3-VL-Embedding-8B"
    reranker_model: str = "Qwen/Qwen3-VL-Reranker-8B"

    # Chroma
    chroma_persist_dir: str = "./data/chroma"

    # RAG
    chunk_size: int = 512
    chunk_overlap: int = 128
    retrieval_top_k: int = 5

    # Agent
    max_loops: int = 3
```

**设计要点：**
- Embedding 和 Reranker 均通过 SiliconFlow 云端 API 调用，无需本地 GPU/大内存
- 启动时间从 ~30s（本地加载 400MB 模型）降至 < 5s
- 向量维度从 512（bge-small）提升至 4096（Qwen3-VL-Embedding-8B）

### 5.2 RAG 模块（rag_pipeline.py）

实现多格式文档加载 → 智能分块 → 混合检索 → 重排序的完整 RAG Pipeline。

#### 5.2.1 文档加载

支持四种格式，通过扩展名路由：

| 格式 | 解析器 | 说明 |
|------|--------|------|
| PDF | `pypdf.PdfReader` | 逐页提取文本 |
| DOCX | `python-docx` | 提取所有段落 |
| MD / TXT | 原生 `open()` | UTF-8 读取 |

#### 5.2.2 文本分块

自实现 `RecursiveCharacterTextSplitter`，针对中文优化分隔符层级：

```
"\n\n" → "\n" → "。" → "." → " " → ""
```

支持可配置的 `chunk_size`（默认 512）和 `chunk_overlap`（默认 128）。

#### 5.2.3 混合检索

```
用户查询
    │
    ├── 向量检索 (Chroma + SiliconFlow Embedding) → top_k * 2
    ├── BM25 检索 (rank_bm25 + jieba 分词)        → top_k * 2
    │
    └── RRF 融合 (k=60)
        │
        └── Cross-encoder 重排序 (Qwen3-VL-Reranker-8B API)
            │
            └── 返回 top_k 结果
```

**RRF（Reciprocal Rank Fusion）公式：**

```
score(d) = Σ 1 / (k + rank_i(d))
```

其中 k=60，对向量检索和 BM25 的排名进行融合。

#### 5.2.4 云端 Reranker

```python
def _rerank(query, docs):
    resp = requests.post(
        f"{settings.siliconflow_base_url}/rerank",
        json={
            "model": settings.reranker_model,
            "query": query,
            "documents": [d.page_content for d in docs],
        },
    )
    # 按 relevance_score 降序排列
    return sorted_docs
```

### 5.3 LangGraph Agent（agent_graph.py）

整个项目的核心模块，实现 6 节点状态图。

#### 5.3.1 图结构

```python
def build_graph():
    graph = StateGraph(AgentState)

    graph.add_node("retrieve", retrieve_node)
    graph.add_node("decide", decide_node)
    graph.add_node("execute", execute_node)
    graph.add_node("reflect", reflect_node)
    graph.add_node("human_confirm", human_node)
    graph.add_node("answer", answer_node)

    graph.set_entry_point("retrieve")
    graph.add_edge("retrieve", "decide")

    graph.add_conditional_edges("decide", route_after_decide, {
        "tool": "execute",
        "answer": "answer",
        "human_confirm": "human_confirm",
        "retrieve_again": "retrieve",
    })

    graph.add_edge("execute", "reflect")
    graph.add_conditional_edges("reflect", should_continue, {
        "continue": "decide",
        "end": "answer",
    })

    graph.add_edge("human_confirm", "execute")
    graph.add_edge("answer", END)

    return graph
```

#### 5.3.2 关键节点实现

**retrieve_node** — 检索相关文档：
- 从 `messages` 中提取最后一条用户消息
- 调用 `RAGPipeline.hybrid_search()` 执行混合检索
- 重置 `loop_count` 为 0

**decide_node** — LLM 决策下一步动作：
- 将对话历史、检索结果、工具结果、循环次数组装为 prompt
- 调用 DeepSeek API 输出单一决策词：`tool` / `answer` / `retrieve_again` / `human_confirm`
- 无效输出时默认降级为 `answer`

**execute_node** — 执行工具调用：
- 通过关键词匹配选择工具（避免额外的 LLM 调用）
- 支持 `calculator`（数学表达式求值）和 `datetime_tool`（日期时间查询）
- 工具结果以 `role: "tool"` 消息写入 state

**reflect_node** — 评估信息充分性：
- `loop_count += 1`
- 达到 `MAX_LOOPS`（3 轮）时强制终止
- 调用 LLM 评估：`continue`（回到 decide 重新规划）或 `end`（生成回答）

**human_node** — 人工确认暂停点：
- 使用 LangGraph `interrupt()` 暂停图执行
- Streamlit UI 检测到 `GraphInterrupt` 异常后展示确认按钮
- 用户操作后通过 `Command(resume=...)` 恢复执行

**answer_node** — 生成最终回答：
- 汇总检索文档、对话历史、工具结果为 prompt
- 调用 LLM 生成中文综合回答
- 支持多轮对话上下文（最近 10 轮）

#### 5.3.3 对话记忆

通过 LangGraph `MemorySaver` checkpoint 实现：
- 每次对话分配 `thread_id`，同一线程内上下文自动累计
- `agent_graph.py` 中 `_node_context()` 提取最近 10 轮对话注入 LLM prompt
- 侧栏「清空对话历史」按钮重置 `thread_id` 和对话状态

### 5.5 MCP 协议集成（mcp_server.py）

自建只读 Filesystem MCP Server，通过 stdio 与 Agent 通信。

**提供的工具：**

| 工具名 | 功能 | 安全措施 |
|--------|------|----------|
| `read_file` | 读取指定文件内容 | 路径遍历防护（`realpath` 校验） |
| `list_dir` | 列出目录中的文件和子目录 | 同上，限制在 `MCP_ALLOWED_PATH` 内 |

**路径安全校验：**
```python
def _safe_path(path):
    allowed = os.path.realpath(settings.mcp_allowed_path)
    full = os.path.realpath(os.path.join(allowed, path))
    if not full.startswith(allowed):
        raise ValueError(f"Path traversal denied: {path}")
    return full
```

## 9. 技术决策与演进

### 9.1 已实现的关键决策

| 决策 | 原因 |
|------|------|
| 使用原生 Chroma 而非 langchain-chroma | 减少依赖链，更灵活控制 Embedding 逻辑 |
| Embedding/Reranker 使用云端 API | 消除本地 1.7GB 模型存储和 ~30s 冷启动 |
| 工具选择用关键词匹配而非 LLM function calling | 减少 API 调用次数，降低延迟 |
| 自实现 RecursiveCharacterTextSplitter | 针对中文优化分隔符层级，避免依赖 langchain-text-splitters |
| 使用 MemorySaver 而非持久化 Checkpointer | 轻量级，适合单机开发场景 |

### 9.2 后续演进方向

- **多模态文档**：接入 OCR 实现对扫描件/图片内文字的检索
- **MCP 生态扩展**：接入更多 MCP Server（GitHub、Notion、Slack）

## 10. 总结

本项目是一个面向 Agent 开发练习的完整工程项目，从最初的设计文档到最终实现，完整覆盖了 RAG 全流程（文档加载→分块→Embedding→混合检索→重排序）、LangGraph 状态图设计（6 节点 + 条件路由 + 循环控制 + Human-in-the-Loop）、MCP 协议集成（自建 Server + 安全校验）和工程化实践（日志、配置、测试 33 个用例）。

在实现过程中，根据实际情况对技术选型做了务实调整：将本地 Embedding 模型替换为 SiliconFlow 云端 API 以消除冷启动延迟，用关键词匹配替代 LLM function calling 以减少 API 消耗，用原生 Chroma 替换 langchain-chroma 以减少依赖复杂度。这些决策体现了在工程实践中平衡理想架构和实际约束的能力。
